# Database Conventions

PostgreSQL 18 with pgvector. The schema is versioned with Flyway in `services/core-api/src/main/resources/db/migration`.

## Migrations
- File name: `V<number>__<snake_case_description>.sql` (two underscores). Numbers are sequential integers.
- One migration per coherent change. A merged migration is **never edited**: fix forward with a new migration.
- Migrations must work on an empty database **and** on the previous production state.
- `flyway clean` is disabled. Hibernate never creates or alters tables (`ddl-auto=validate`).
- Extensions are created with `CREATE EXTENSION IF NOT EXISTS`. On managed databases a DBA may pre-create them, which keeps the migration a no-op.

## Naming
| Object | Convention | Example |
| --- | --- | --- |
| Table | plural `snake_case` | `organization_memberships` |
| Column | `snake_case` | `created_at` |
| Primary key | `id uuid` | `id uuid primary key` |
| Foreign key column | `<entity>_id` | `organization_id` |
| Constraint | `pk_`, `fk_`, `uq_`, `ck_` + table + columns | `uq_departments_organization_id_code` |
| Index | `ix_<table>_<columns>` | `ix_tasks_organization_id_status` |

## Column standards
- Identifiers: `uuid`. Values are generated by the application (UUID v7 recommended for index locality), so they are not guessable sequential integers exposed in URLs.
- Time: `timestamptz` only, stored and returned in UTC. Every connection runs `SET TIME ZONE 'UTC'`.
- Audit columns on business tables: `created_at`, `updated_at` (`timestamptz not null`), plus `created_by` / `updated_by` once authentication exists.
- Optimistic locking: `version bigint not null default 0` on mutable aggregates.
- Enumerations: `text` with a `CHECK` constraint (evolves with a migration; no PostgreSQL enum types).
- Money: `numeric(19,4)` with a currency column. Never floating point.
- Embeddings: `vector(<dimensions>)`, with the dimension fixed per embedding model and an HNSW index where similarity search is needed.

## Multi-tenancy (planned from Sprint B1)
- Every organization-owned table has `organization_id uuid not null` referencing `organizations(id)`.
- Uniqueness is scoped per organization, e.g. `unique (organization_id, code)`.
- Composite foreign keys including `organization_id` are preferred between tenant tables, so a row can never reference another organization's row.
- Every index used for business queries starts with `organization_id`.
- PostgreSQL Row-Level Security is a planned **defence in depth** layer. The primary enforcement stays in the application (see `docs/architecture/SECURITY_ARCHITECTURE.md`).
